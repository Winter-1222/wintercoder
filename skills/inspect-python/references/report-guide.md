# Python 源码概览的报告口径

## 如何解释 JSON

| 字段 | 含义 |
| --- | --- |
| target | 本次扫描的项目相对路径 |
| files_scanned | 已尝试读取的 Python 文件数，包含解析失败的文件 |
| files_parsed | 成功解析并计入 totals 的文件数 |
| truncated | 超过 --max-files 限制，还有文件未扫描 |
| complete | 没有截断且 errors 为空；只代表定义的扫描范围完成 |
| totals | 成功解析文件的物理行数、函数数、类数 |
| files | 每个成功解析文件的统计、定义位置和导入模块名 |
| errors | 读取、大小或语法错误；只记录错误类型和位置，不回显源码 |
| details_truncated | 当前文件定义或导入明细超过 20 条；计数仍是完整统计 |

函数包含普通函数、异步函数、类方法和嵌套函数；类包含嵌套类。物理行数包含注释与空行。导入模块名去重，from 导入保留模块与相对层级，不能据此确定导入是否在运行时发生。

## 完整性和限制

- 默认最多尝试 100 个 .py 文件，可用 --max-files 在 1—500 之间调整；单文件最多读取 256 KiB。
- 跳过隐藏目录、node_modules、__pycache__、build、dist、out，以及符号链接和 Windows junction。文件采用固定排序扫描。
- 目标必须在当前项目内；目标本身不能位于被排除目录，也不能借助链接进入其他位置。
- 有任何 errors 时退出码为 1；目标无效、没有 Python 文件或遍历失败时退出码为 2。完整成功和仅因文件数截断都返回 0，必须另外检查 truncated。
- 用户要全目录统计而结果被截断时，应缩小分批扫描范围或提高上限。不要把部分结果称为整个项目结果。
- AST 来自语法解析，脚本不会执行 import。它不能证明运行时调用链、动态导入、插件加载、测试覆盖率或系统正确性。
- 函数多、文件长只表示规模，不能单独作为“代码质量差”的结论。

## 回答例子

“在 src/jixue/domain 范围内尝试了 X 个文件，成功解析 Y 个，存在 Z 个错误。统计包含类方法和嵌套函数。入口候选来自定义位置；是否由 Bridge 实际调用，需要继续阅读调用方。”

当用户追问完整链路时，用文件工具读取调用方与被调用方，并分别标注静态统计事实和经过源码确认的关系。
