# 开发、教学与复盘约定

## 1. 注释语言

源码注释与 docstring 使用中文，说明“为什么”和边界条件，不逐行翻译代码。类名、函数名、协议字段和第三方 API 名称保持英文，避免自造翻译导致检索困难。

好的注释：

```python
# 标准输出属于 NDJSON 协议通道，普通日志必须写入标准错误。
```

不需要的注释：

```python
# 把计数器加一。
counter += 1
```

## 2. 每章文档布局

```text
docs/chapters/01-llm-ui/
├─ README.md          # 教学：概念、设计、代码导航和练习
├─ DEVLOG.md          # 开发过程、决策、问题与提交
└─ MANUAL_TEST.md     # 手动步骤、预期、实际与坑
```

进入新章时才创建该章目录，避免提前生成大量空文档。

## 3. 开发循环

每个小步遵循：

1. 在教学文档写一句本步要解决的问题。
2. 先写领域类型或失败测试。
3. 实现最小代码。
4. 运行相关自动化测试。
5. 按手测文档操作一次并记录实际结果。
6. 在 DEVLOG 写遇到的错误与取舍。
7. 检查 diff 后提交 Git。

## 4. 测试分层

- 单元测试：消息转换、JSON 碎片、权限规则、批次分区等纯逻辑。
- 组件测试：使用 FakeLLM、FakeTool、FakeTransport，不访问网络。
- 集成测试：Python Bridge 与 Electron IPC、会话落盘等进程或文件边界。
- 手动测试：真实 DeepSeek、真实窗口、真实 MCP 和用户确认交互。

真实 API 不放进默认自动化测试，以免测试不稳定和产生费用。

## 5. 密钥与日志

- 示例配置只写 `${DEEPSEEK_API_KEY}`、`${AMAP_MCP_KEY}`。
- API Key 不能出现在异常字符串、请求 dump、截图或开发日志中。
- 默认日志记录请求 ID、模型、耗时、Token、事件类型，不记录完整对话正文。
- 需要调试正文时使用临时显式开关，结束后删除产生的日志。

## 6. Git 约定

提交格式：`类型(范围): 中文说明`。

常用类型：

- `feat`：新增功能。
- `fix`：修复问题。
- `test`：补充测试。
- `docs`：文档与复盘。
- `refactor`：不改变行为的重构。
- `chore`：工程配置。

提交前至少检查：相关测试通过、无密钥、无运行数据、文档同步、注释为中文。
