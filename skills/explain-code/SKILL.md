# 解释源码

根据用户指定的文件或问题，找出“入口 → 关键控制流 → 结果”的最短完整链路。

- 用 read_file、grep、glob 获取实际代码依据；用户没有指定文件时，从项目 README 和相关入口开始。
- 先交代用户动作如何进入程序，再解释关键函数之间传了什么、结果怎样返回；给出项目相对文件路径和行号。
- 重点解释初学者容易误解的异步等待、工具调用与结果配对、权限检查等概念；只讲当前链路涉及的内容。
- 区分已实现行为、提示词约定和改进建议；不要把设计意图当成测试结论。
- 用一个具体输入串起流程，最后给出启动方式和可观察的手测现象。用户只问概念时，不必改代码或运行程序。

建议回答顺序：当前行为、关键代码链、具体例子、验证方法。
